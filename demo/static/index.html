Pick a real held-out test window (never seen in training). The detector outputs class probabilities; the attack score is 1 − P(Benign). With a calibrated rule the window is flagged only if the score exceeds a threshold chosen on validation data so that just 5 % or 1 % of benign traffic raises an alarm.

A black-box attacker that only sees the IDS verdict tries to make a detected attack window look Benign. It may only change its own packets: pad them (≤ MTU), slow down to r × the rate (r ≥ 0.1), and set the TTL to a typical benign value. Protocol, flags and headers cannot change. The hardened model is the same network after two rounds of adversarial training (WP5).

Real deployment run (Flower 1.42): the server ran on an Azure VM; 10 clients each trained on their own share of the data, 5 on a second Azure VM and 5 on this laptop, across the internet over TLS. Only model weights travel; raw traffic never leaves a client. Replay the recorded run round by round. This deployment run used the v1 MLP (13k parameters) and was checked against the simulator (identical test macro-F1); the v2 federated results below come from the simulator.
